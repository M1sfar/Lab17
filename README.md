# Практическая работа №17: Разработка документации и отчетных форм для внедрения программных средств

## Описание проекта
Данный репозиторий содержит комплект отчетной технической документации для оценки готовности к внедрению кандидата выпуска 1.5.0-rc1 (учебный кейс DOC-17). 

Основная задача работы — проведение аудита исходного пакета поставки (release_packet.json), проверка связности требований со спецификацией (service_spec.md), выявление инфраструктурных и логических противоречий, а также формирование регламентов для развертывания и обслуживания системы.

---

## Структура репозитория и навигация по пакету

Все документы пакета взаимосвязаны и оформлены в формате Markdown. Ниже приведены ссылки на соответствующие отчетные формы:

* **[checkpoint_1.md](./checkpoint_1.md)** — Промежуточный результат контроля проекта.

* **[release_passport.md](./release_passport.md) — Паспорт выпуска**
  * Содержит: Общие сведения о релизе, требования к среде (Linux x64, Python, PostgreSQL), состав поставки, параметры конфигурации, зависимости миграции M015 и текущий статус готовности.
* **[traceability.md](./traceability.md) — Матрица трассировки**
  * Содержит: Карточку покрытия архитектурных требований (R_CREATE, R_ACCESS, R_IDEMPOTENCY, R_RESTORE, R_PERFORMANCE) результатами автоматизированных тестов с анализом причин блокировок.
* **[test_protocol.md](./test_protocol.md) — Протокол проверки**
  * Содержит: Анализ фактически известных результатов испытаний, перечень критических несоответствий в версиях руководства и конфигурации, а также план корректирующих действий.
* **[release_runbook.md](./release_runbook.md) — Регламент выпуска и обслуживания**
  * Содержит: Предварительные условия, логические этапы развертывания новой схемы S2, оценку критичности (веса) каждого шага, окно обслуживания, а также сценарий отката (Rollback) на версию 1.4.2.
* **[documentation_changes.md](./documentation_changes.md) — Изменения в эксплуатационной документации**
  * Содержит: Перечень замечаний к текущей документации и обновленный, исправленный фрагмент Руководства оператора по действиям при возникновении сетевых таймаутов.
* **[release_decision.md](./release_decision.md) — Итоговое решение (Релиз-директива)**
  * Содержит: Официальный мотивированный отказ в выводе кандидата 1.5.0-rc1 на продуктивную среду и перечень условий, необходимых для повторного пересмотра.

## Ключевые результаты аудита пакета

В ходе анализа исходных данных (release_packet.json и service_spec.md) были обнаружены критические дефекты, из-за которых выпуск заблокирован:
1. **Инфраструктурный сбой (T04):** Тест восстановления данных из бэкапа имеет статус "blocked" с ошибкой "restore-target-unavailable". Безопасный откат системы в случае аварии не гарантирован.
2. **Слепая зона (T05):** Тест производительности (R_PERFORMANCE) не запускался ("not_run"), что нарушает требования к перцентилю скорости ответа (p95 <= 800 мс) при нагрузке в 1000 заявок.
3. **Устаревшая документация:** В составе пакета поставляется руководство оператора версии 1.4.2, не описывающее логику работы новой функции category_required и механизмы работы с idempotency_key.
